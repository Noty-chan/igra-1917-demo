# Сетевая игра

Рабочий адрес: https://igra1917.85.159.231.3.sslip.io/

Одна общая партия. Ведущий входит в режиме «Ведущий» с отдельным паролем. Игроки вводят своё имя и общий пароль игроков; повторный вход с тем же именем возвращает того же участника и персонажа. Имя участника не менять во время игры. Зрители используют пароль игроков и режим «Зритель», который предварительно включает ведущий. Войти в другой режим можно через «Выйти».

Общие действия сохраняются в SQLite до подтверждения клиенту и рассылаются через WebSocket. При обрыве связи клиент переподключается и получает свежую сессию; неподтверждённые действия автоматически не повторяются. Броски генерируются на сервере. Цели, кровь, скрытые локации, записи журнала и листы других персонажей фильтруются до отправки в браузер. Ведущий видит всю информацию. Сценарий `content/game.js` через HTTP недоступен.

Текущая версия намеренно простая: одна партия, общий пароль игроков, имя — идентификатор участника. Это не система отдельных личных аккаунтов: знающий общий пароль и чужое имя может войти под ним. Добавленные NPC, их картинки, заметки и изменённые описания теперь хранятся в общей базе. Состояние старого демо в localStorage автоматически не переносится и не удаляется. Статические NPC и персонажи в репозитории сохраняются при обновлениях. GitHub Pages остаётся отдельным локальным демо, а не сетевым клиентом.

## Сервер

- Node.js 24, единственная npm-зависимость `ws`; SQLite встроен в Node.js.
- Приложение: `/opt/igra-1917`; Node: `/opt/igra-node/bin/node`.
- Служба: `igra-1917.service`, пользователь `igra-1917`, порт только `127.0.0.1:4180`.
- База: `/var/lib/igra-1917/game.sqlite`. Не заменять её при обновлении приложения.
- Пароли и настройки: `/etc/igra-1917.env`, доступ только root. Пример настроек — `server/.env.example`. Реальные пароли в репозиторий не добавлять.
- Nginx: `/etc/nginx/sites-available/igra-1917`. Другой сайт VPS не изменён.
- HTTPS: сертификат Let's Encrypt, автоматическое продление Certbot.
- Ежедневные резервные копии SQLite: `/var/lib/igra-1917/backups/`, последние 7 дат. Таймер `igra-1917-backup.timer`. Это копии на том же VPS, а не внешнее хранилище.

## Обновление и проверка

Загрузить `dist/`, `server/`, `package.json`, `package-lock.json` в `/opt/igra-1917`. Затем:

```sh
cd /opt/igra-1917
PATH=/opt/igra-node/bin:$PATH npm ci --omit=dev --ignore-scripts
systemctl restart igra-1917
curl -fsS https://igra1917.85.159.231.3.sslip.io/api/health
journalctl -u igra-1917 -n 40 --no-pager
```

Локальные проверки: `npm ci`, `npm test`, `npm run test:network`. Для локального запуска задать разные `GM_PASSWORD` и `PLAYER_PASSWORD`, `COOKIE_SECURE=false`, `DB_PATH` на тестовую базу, затем `npm start`. Минимум Node.js 22.13.

Восстановление из копии: остановить службу, сохранить текущую базу, заменить `game.sqlite` выбранной копией, убедиться, что владелец `igra-1917`, запустить службу. Не подменять активную базу, не удалять её WAL/SHM во время работы.

Проверено: серверные права, конкуренция за персонажа, раскрытие целей, кровь, серверные броски и воля, скрытый журнал, зрители, сохранение после перезапуска; два независимых браузера и мобильная ширина.
