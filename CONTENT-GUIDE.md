# Как добавлять материалы

Основной файл — `dist/content/game.js`. Тексты представлены обычными строками: HTML не требуется. Пустая строка разделяет абзацы. Перед публикацией отмечаем, какие образцы уже заменены утверждёнными материалами.

- `title`, `chronology` — название и время действия.
- `house.image` — существующая иллюстрация особняка. `house.intro` и `house.history` пока пусты: будут заполнены вашим текстом. Пустая история не создаёт секцию на странице.
- `days` — дни в нужном порядке: постоянный `id`, заголовок, дата/месяц, период, вступительный текст. Пока нет точных дат, используем сентябрь 1917.
- `characters` — публичные имя, роль, краткое описание, портрет. `layers` — последовательно раскрываемые всем сведения. `privateSections` — только личный лист и просмотр ведущего. `stats` — название и значение каждой характеристики.
- Актуальные листы персонажей используют `attributes`, `abilities`, `disciplines`, `virtues`, `humanity`, `willpower` и `bloodPool`; игрок видит их только в своём листе. `goals.main` хранит личную и игровую цель, `goals.traitor` — отдельную цель предателя. Состояние `goals.mainVisible` и `goals.traitorVisible` меняет ведущий независимо. Не импортируйте возраст, игрока, sire, backgrounds, специализации, информатику, вождение или уличное чутьё.
- Для клиентского показа есть парольный экран; он не защищает данные от чтения исходников и обхода JavaScript. Все материалы из `dist` доступны посетителю после входа. Не используйте демо-версию для реальных тайн до серверной фильтрации по роли и владельцу.
- `rooms` — название, превью, `initialLevel`, массив `layers`. `image: null` заменяется на `{src: 'assets/имя.jpg', alt: 'Описание изображения'}`. Изображение появится в карточке и при осмотре. Файл кладём в `dist/assets`.
- `npcs` — аналогичные публичные материалы и уровни. Изначально все NPC скрыты; ведущий открывает их через интерфейс.

`layers` содержит объекты `{title: 'Заголовок', text: 'Текст'}`. Ноль означает базовое превью; каждый следующий уровень добавляет следующий объект массива. Число уровней не ограничено двумя. Личные тайны не помещаем в публичные `layers`.

Для отдельного портрета используем `{src: 'assets/портрет.jpg', alt: 'Имя'}`. Все девять игровых портретов теперь отдельные изображения в `dist/assets/characters`. `deathPortrait` — изображение при отметке смерти. `description` — описание из согласованного DOCX, `nature` и `mask` — архетипы, `natureNote` — уточнение цели натуры. У Белозёрова `concealedIdentity: true`: публичные поля заменяются вопросами. Поколение хранится только числом в строке, без «-е».

`playerGuide` — общие правила. Объявления находятся в состоянии `events`, редактируются через сайт и сохраняются в браузере; их публикация не меняет исходный файл. Семь элементов `health` в состоянии принимают 0 (пусто), 1 (ударное), 2 (летальное), 3 (аггравированное). `willpowerCurrent` — текущая воля; постоянная хранится в содержании. `journal` хранит историю бросков и сообщений, комментарии и признак скрытой записи.

Сохраняйте существующие `id`, даже если изменились имя или расположение карточки: по ним связаны выбор, раскрытие и заметки. Для нового материала нужен новый уникальный ID из латинских букв, цифр и дефисов. При удалении персонажа связанное состояние перестанет отображаться.

Пока это локальный макет: новые тексты и изображения можно присылать партиями. Реальные личные секреты будут подключены после серверной защиты и совместных сессий.
